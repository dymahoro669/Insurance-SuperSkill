# Evolution Auditor 设计文档

> 六维审计系统，对每次进化结果进行独立、全面的质量审查。

## 1. 设计原则

Evolution Auditor 是进化引擎的"独立监督者"，与进化引擎解耦，确保进化质量不被"自我评价"所蒙蔽。

- **独立性**: Auditor 不参与进化决策，只做事后审查
- **全面性**: 6个维度覆盖技术、业务、合规、效率
- **可量化**: 每个维度 0-100 分，总分决定是否发布

## 2. 六维评分模型

### 2.1 INT - 完整性 (Integrity)

| 检查项 | 权重 | 通过标准 |
|--------|------|---------|
| SKILL.md 必要段落齐全 | 30% | 5个段落全部存在 |
| 来源Skills表格完整 | 25% | 映射表全部原始Skill已列出 |
| 测试用例覆盖 | 25% | ≥20个回归用例 + 5个冒烟用例 |
| 配置文件无缺失 | 20% | manifest/router/pii/rules 均有效 |

### 2.2 USA - 可用性 (Usability)

| 检查项 | 权重 | 通过标准 |
|--------|------|---------|
| 路由测试通过率 | 35% | ≥90% 测试用例路由正确 |
| CLI 命令可用 | 25% | 17个命令均可执行 |
| 安装脚本可运行 | 25% | install.ps1 无报错完成 |
| 文档可读性 | 15% | 关键段落无乱码/格式错误 |

### 2.3 CON - 一致性 (Consistency)

| 检查项 | 权重 | 通过标准 |
|--------|------|---------|
| 跨Skill术语统一 | 30% | 同一概念在不同Skill中表述一致 |
| 版本号一致 | 25% | manifest 与各 SKILL.md 版本一致 |
| 依赖声明一致 | 25% | Skill 依赖与实际调用一致 |
| 路由表与SKILL.md一致 | 20% | router.yaml 关键词与 SKILL.md 触发词一致 |

### 2.4 EFF - 效率 (Efficiency)

| 检查项 | 权重 | 通过标准 |
|--------|------|---------|
| 评价响应时间 | 35% | LLM评价平均响应 < 5秒 |
| 路由决策时间 | 25% | 意图识别 < 500ms |
| 资源占用 | 25% | 单次调用内存 < 100MB |
| 并发处理 | 15% | 支持 ≥10 并发请求 |

### 2.5 PRO - 专业性 (Professionalism)

| 检查项 | 权重 | 通过标准 |
|--------|------|---------|
| 术语规范 | 35% | 术语规范性得分 ≥ 80 |
| 行业深度 | 25% | 覆盖领域核心场景 ≥ 80% |
| 逻辑严谨 | 25% | 逻辑自洽性得分 ≥ 85 |
| 示例质量 | 15% | 测试用例具有代表性 |

### 2.6 REA - 合理性 (Reasonableness)

| 检查项 | 权重 | 通过标准 |
|--------|------|---------|
| 数值合理 | 35% | 数值合理性得分 ≥ 85 |
| 结论有据 | 25% | 输出结论有明确依据 |
| 边界处理 | 25% | edge case 覆盖 ≥ 20% |
| 异常处理 | 15% | error case 有友好降级 |

## 3. 评分计算

```
维度分 = Σ(检查项得分 × 检查项权重)
总分 = Σ(维度分 × 维度权重)

维度权重:
  INT: 20%, USA: 20%, CON: 15%, EFF: 15%, PRO: 15%, REA: 15%

通过阈值:
  - 发布: 总分 ≥ 80 且 无维度 < 60
  - 警告: 总分 60-79 或 有维度 < 60
  - 拒绝: 总分 < 60 或 有维度 < 40
```

## 4. 审计流程

```
1. 接收进化结果包（skill改动 + 测试报告 + 评价数据）
2. 并行执行6维度检查（6个独立检查器）
3. 汇总评分 → 生成审计报告
4. 判定: 通过 / 警告 / 拒绝
5. 如通过 → 允许发布
6. 如拒绝 → 生成拒绝原因 → 退回进化引擎重新规划
```

## 5. 审计报告格式

```json
{
  "audit_id": "AUD-2026-0531-001",
  "plan_id": "EVP-2026-0531-001",
  "audited_at": "2026-05-31T03:00:00Z",
  "dimensions": {
    "INT": { "score": 92, "passed": true, "findings": [] },
    "USA": { "score": 88, "passed": true, "findings": ["CLI import命令未完整实现"] },
    "CON": { "score": 90, "passed": true, "findings": [] },
    "EFF": { "score": 85, "passed": true, "findings": ["回归测试运行时间较长"] },
    "PRO": { "score": 91, "passed": true, "findings": [] },
    "REA": { "score": 89, "passed": true, "findings": [] }
  },
  "total_score": 89.2,
  "verdict": "pass",
  "recommendations": [
    "建议完善 CLI import 命令的实现",
    "建议优化回归测试执行效率"
  ]
}
```

## 6. 与进化引擎的交互

```
进化引擎        Auditor        结果
    │            │             │
    ├─ 提交进化包 ─→│             │
    │            ├─ 6维审计     │
    │            ├─ 生成报告    │
    │←─ 返回判定 ──┤             │
    │            │             │
    ├─ 通过 ─────→│             ├─ 发布新版本
    ├─ 警告 ─────→│             ├─ 发布 + 记录问题
    └─ 拒绝 ─────→│             └─ 回滚 + 重新规划
```
