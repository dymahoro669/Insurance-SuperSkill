# L2/L3 评价服务设计文档

> 分层质量评价系统：L2 专业评价员（模拟人类专家）+ L3 领域权威（真实专家介入）。

## 1. 分层架构

```
┌─────────────────────────────────────────────┐
│  L1 本地评价器 (local-evaluator)              │
│  → 规则/LLM 快速初筛，零成本                  │
│  → 输出: pass/warn/fail + 8维度得分           │
├─────────────────────────────────────────────┤
│  L2 专业评价员 (Professional Reviewer)        │
│  → 模拟保险专家角色，深度语义评价              │
│  → 输出: 专业评分 + 改进建议 + 案例对比        │
├─────────────────────────────────────────────┤
│  L3 领域权威 (Domain Authority)               │
│  → 真实人类专家（精算师/核保员/理赔员等）      │
│  → 输出: 权威认证 + 行业对标 + 合规背书        │
└─────────────────────────────────────────────┘
```

## 2. L2 专业评价员

### 2.1 角色定义

L2 评价员是模拟保险行业专家的 AI Agent，每个领域有专属评价员：

| 领域 | 评价员角色 | 专业背景 |
|------|-----------|---------|
| 核保 | Senior Underwriter | 10年+ 核保经验，熟悉各险种核保规则 |
| 理赔 | Claims Manager | 10年+ 理赔管理，熟悉理赔流程和法规 |
| 精算 | Fellow Actuary | FSA/FCAS 资格，熟悉定价和准备金评估 |
| 合规 | Compliance Officer | 法律+保险双背景，熟悉监管法规 |
| 营销 | Insurance Broker | 10年+ 保险销售，熟悉客户需求分析 |
| ... | ... | ... |

### 2.2 L2 Prompt 模板

```markdown
# 角色
你是一位{领域}资深专家，拥有{专业资格}，在保险行业工作超过10年。
你的任务是对 AI 生成的{领域}回答进行专业评价。

# 评价标准
1. 专业深度：回答是否体现了行业专家级别的知识深度？
2. 实务准确：回答中的流程、规则、数值是否符合行业实际？
3. 场景覆盖：是否覆盖了该领域的主要业务场景？
4. 可执行性：按照回答操作，是否能在实际工作中落地？
5. 风险意识：是否识别并提示了潜在的风险点？

# 输入
用户问题：{user_input}
AI回答：{skill_output}

# 输出格式
```json
{
  "professional_score": <0-100>,
  "practical_accuracy": <0-100>,
  "scenario_coverage": <0-100>,
  "executability": <0-100>,
  "risk_awareness": <0-100>,
  "overall": <0-100>,
  "evaluation": "<详细评价，200-500字>",
  "improvements": ["<改进建议1>", "<改进建议2>"],
  "benchmark": "<与行业标准实践的对比>"
}
```
```

### 2.3 触发条件

- L1 评价结果为 **warn** 或 **fail**
- L1 某维度得分 < 60
- 随机抽样：5% 的 pass 结果也会触发 L2（用于监控 L1 评价质量）
- 用户主动要求专家评价

### 2.4 输出示例

```json
{
  "professional_score": 82,
  "practical_accuracy": 78,
  "scenario_coverage": 85,
  "executability": 80,
  "risk_awareness": 75,
  "overall": 80,
  "evaluation": "该回答在理赔材料清单和赔付计算方面表现良好，但缺少对理赔时效的说明，且未提示用户注意理赔申请的时间限制（通常出险后10日内报案）。",
  "improvements": [
    "补充理赔时效要求（报案时限、材料提交时限）",
    "增加理赔进度查询渠道说明",
    "提示用户保留原始票据的重要性"
  ],
  "benchmark": "与行业标准的理赔服务话术相比，缺少主动关怀和后续跟进提示。"
}
```

## 3. L3 领域权威

### 3.1 介入条件

L3 是真实人类专家，仅在以下情况介入：

1. L2 评价结果与 L1 差异 > 20 分（需要仲裁）
2. 涉及重大合规风险（如 D4 合规红线得分 < 40）
3. 新型业务场景，无历史评价数据参考
4. 季度/年度质量审计

### 3.2 工作流程

```
1. 系统标记需要 L3 评价的案例
2. 发送通知给对应领域的认证专家
3. 专家登录评价平台，查看 L1/L2 结果 + 原始输入输出
4. 专家独立给出评价（不知道 L1/L2 的具体得分）
5. 系统汇总 L1/L2/L3 三方评价
6. 如 L3 与 L1/L2 差异大 → 触发评价器校准流程
```

### 3.3 专家认证

| 级别 | 要求 | 评价权限 |
|------|------|---------|
| L3-初级 | 行业3年+经验 | 单项评价 |
| L3-中级 | 行业5年+经验 + 专业资格 | 批量评价 + 评价员培训 |
| L3-高级 | 行业10年+经验 + 知名专家 | 仲裁 + 标准制定 |

### 3.4 L3 评价模板

```markdown
# 案例信息
- Skill: {skill_id}
- 用户输入: {user_input}
- AI输出: {skill_output}
- L1得分: {l1_score}
- L2得分: {l2_score}

# 请回答以下问题
1. 该回答是否存在事实性错误？如有，请指出。
2. 该回答是否符合行业最佳实践？
3. 如果这是您的团队成员的回答，您会给什么评分（0-100）？
4. 该回答是否可以直接用于客户服务？如不能，需要哪些修改？
5. 其他建议：

# 您的评分
专业度：___  实务性：___  合规性：___  综合：___
```

## 4. 三层评价数据流

```
用户请求 → Skill执行 → L1评价 ─┬─→ pass → 返回用户
                               │
                               ├─→ warn/fail → L2评价 ─┬─→ 一致 → 返回用户 + 改进建议
                               │                       │
                               │                       └─→ 差异大 → L3仲裁
                               │
                               └─→ 随机抽样(5%) → L2评价 → 监控L1质量
```

## 5. 评价校准

当 L3 专家评分与 L1/L2 差异 > 15 分时，触发校准：

```
1. 收集差异案例（≥10个）
2. 分析差异模式（L1过严/过松？L2偏差方向？）
3. 调整评价维度权重或Prompt
4. 重新运行历史案例验证
5. 发布新版本的评价器配置
```

## 6. 成本与效率

| 层级 | 单次成本 | 响应时间 | 日处理量 |
|------|---------|---------|---------|
| L1 | ~$0（本地LLM）或 ~$0.01 | < 5s | 无限制 |
| L2 | ~$0.05-0.20 | 5-15s | 10,000+ |
| L3 | ~$50-200（专家时间） | 数小时-数天 | 100-500 |

设计原则：**90% 的案例由 L1 处理，9% 由 L2 处理，1% 由 L3 处理**。
