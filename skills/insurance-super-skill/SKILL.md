## 能力描述

主索引Skill是整个Insurance-SuperSkill平台的入口和调度中心，承担着用户请求的第一道处理与最后一道把关职责。当用户提出保险相关请求时，主索引负责执行以下核心能力模块：

**1. 意图识别与置信度计算**

主索引内置意图识别引擎，采用多信号加权融合策略，综合关键词匹配、语义相似度分析和上下文加权三项信号，通过softmax归一化计算各子Skill的意图置信度。关键词匹配覆盖12个领域意图类别的精确与模糊匹配；语义相似度基于预训练语言模型计算用户输入向量与Skill描述向量的余弦相似度；上下文加权则结合对话历史一致性、跨Skill场景命中和用户确认意图进行动态加分。该引擎确保在高并发场景下仍能在单次推理周期内完成路由决策，避免额外的Skill调用开销。

**2. 安全守卫集成**

主索引深度集成security-guardian组件，在输入阶段对用户的自然语言请求进行PII（个人可识别信息）脱敏处理，包括但不限于姓名、身份证号、手机号、银行卡号、保单号、地址等敏感字段。脱敏后的占位符随请求流转至各子Skill，在结果返回阶段由security-guardian执行PII还原，确保子Skill在处理过程中不接触真实敏感信息。输出阶段还进行二次扫描，防止任何PII泄露风险，形成"脱敏-处理-还原-审计"的完整安全闭环。

**3. 领域路由**

基于意图识别结果，主索引将用户请求精准映射到12个保险领域子Skill之一，包括核保（ins-underwriting）、理赔（ins-claims）、精算（ins-actuarial）、合规（ins-compliance）、营销（ins-marketing）、保单（ins-policy）、产品（ins-product）、客服（ins-service）、运营（ins-ops）、风险（ins-risk）、技术（ins-tech）和知识（ins-knowledge）。每个领域均配置了丰富的触发关键词和语义描述，支持单领域直接路由与多领域协同路由两种模式。

**4. 跨Skill协同调度**

当用户请求涉及多个保险领域时，主索引根据预定义的5条协同链规则，按序调度多个子Skill执行并聚合结果。协同调度支持串行执行（前一Skill输出作为后一Skill输入）和并行执行（多个独立Skill同时处理，结果合并）两种模式。协同链的触发条件包括：跨领域关键词同时命中、用户明确提及多个主题、以及上下文推断出的关联需求。协同结果按执行顺序分段展示，每段标注来源子Skill，确保输出结构清晰可追溯。

**5. 降级策略**

主索引实施三级降级策略以应对不同置信度场景。第一级为直接路由：当最高意图置信度超过0.7时，直接路由到目标子Skill，保证响应效率。第二级为澄清询问：当最高意图置信度处于0.4至0.7之间，或Top2意图置信度差距小于0.2时，主动向用户发起澄清询问，提供候选领域供用户选择，避免错误路由。第三级为兜底知识：当最高意图置信度低于0.4时，将请求路由至ins-knowledge子Skill，并附带友好提示建议用户提供更精确的描述，确保即使意图完全不明也能给出有价值的响应。

**6. 结果聚合与格式化**

对于多Skill协同场景，主索引负责将各子Skill的返回结果进行智能聚合。聚合策略包括：去重合并（消除重复信息）、优先级排序（按领域相关性排列）、冲突检测（标识不同Skill结论不一致之处）和统一格式化（确保输出风格一致）。单Skill路由场景则直接透传子Skill输出，保持原始信息的完整性。

**7. 本地评价触发**

每次完成结果输出后，主索引自动触发local-evaluator组件，由大模型对本次输出进行8维度语义质量评价。评价维度包括：准确性、完整性、相关性、安全性、可读性、时效性、一致性和实用性。评价结果用于监控平台整体服务质量，并为后续模型优化和路由策略调优提供数据支撑。

**8. 会话状态管理**

主索引维护每个用户会话的完整状态，包括对话历史、已确认意图、活跃Skill上下文和PII映射表。会话状态支持多轮对话中的意图继承与修正，当用户在后续轮次中补充或修改需求时，主索引能够基于历史上下文进行更精准的意图识别和路由决策。会话数据仅在当前会话周期内保留，会话结束后自动清理，符合数据最小化原则。

### 跨Skill协同规则

当用户请求涉及多个领域时，按以下链条协同。协同链的触发条件包括：用户输入同时命中多个领域的关键词、上下文推断出关联需求、或用户明确提及多个主题。每条协同链定义了子Skill的执行顺序、数据传递方式和结果聚合策略。

| 场景示例 | 协同链 | 执行模式 | 数据传递 |
|---------|--------|---------|---------|
| 理赔被拒+申诉 | ins-claims → ins-underwriting → ins-compliance | 串行 | claims输出理赔分析→underwriting输出核保复核→compliance输出合规建议 |
| 产品推荐+报价 | ins-product → ins-marketing | 串行 | product输出产品方案→marketing输出报价与营销话术 |
| 保单审查+续保 | ins-policy → ins-underwriting | 串行 | policy输出保单状态→underwriting输出续保风险评估 |
| 合规审计+风控 | ins-compliance → ins-risk | 并行 | compliance与risk同时执行，结果合并展示 |

协同链执行过程中，主索引负责监控各子Skill的执行状态。若某子Skill执行失败或超时，主索引将根据故障隔离原则，标记该环节异常并继续执行后续环节（如后续环节依赖失败环节输出，则降级为跳过该环节并在最终输出中标注异常）。

### 意图置信度计算

**执行主体**：由 `insurance-super-skill` **内部**的**意图识别引擎**负责计算，不是独立的 Skill。

> 意图识别是路由决策的前置步骤，天然属于主索引的职责范围。将其内嵌在主索引中可避免每轮路由产生额外的 Skill 调用开销，同时意图识别依赖的路由表（`router.yaml`）和会话状态均由主索引持有，耦合度最低。

意图置信度采用 **多信号加权融合** 方法，综合关键词匹配、语义相似度和上下文信息：

```
意图置信度 = softmax(各意图原始得分)

原始得分(skill_i) = α·关键词得分 + β·语义相似度 + γ·上下文加分

其中：
- α = 0.5（关键词权重）
- β = 0.4（语义权重）
- γ = 0.1（上下文权重）

1. 关键词得分 = Σ(命中关键词权重) / 该skill关键词总数
   - 精确匹配（如"核保"）：权重 1.0
   - 模糊匹配（如"保险"）：权重 0.3
   - 未命中：0

2. 语义相似度 = cos(用户输入向量, skill描述向量)
   - 使用预训练语言模型编码
   - 取值范围 [-1, 1]，映射到 [0, 1]

3. 上下文加分：
   - 跨Skill场景命中：相关skill +0.2
   - 对话历史一致性：延续上一轮skill +0.15
   - 用户确认过的意图：+0.3

示例：
用户输入"理赔被拒了，想申诉"
- ins-claims: 关键词命中"理赔"(1.0) → 得分 0.9 → 置信度 0.42
- ins-underwriting: 跨场景"理赔申诉"加分 → 得分 0.6 → 置信度 0.28
- ins-compliance: 跨场景"理赔申诉"加分 → 得分 0.5 → 置信度 0.23
- 其他: 得分接近 0

→ 最高置信度 claims=0.42 < 0.7，但命中跨Skill协同场景
→ 触发协同链：ins-claims → ins-underwriting → ins-compliance
```

### 降级策略

主索引实施三级分层降级策略，确保在不同意图清晰度场景下均能提供最优用户体验：

**1. 直接路由（一级）**

触发条件：最高意图置信度 > 0.7，且Top2意图置信度差距 >= 0.2。

执行逻辑：直接将请求路由到置信度最高的目标子Skill，无需用户确认。此策略适用于意图表达明确、领域归属清晰的场景，能够最大化响应效率，减少用户等待时间。直接路由后，主索引在输出中标注路由到的子Skill名称，便于用户追溯。

**2. 澄清询问（二级）**

触发条件：最高意图置信度处于0.4至0.7之间，或Top2意图置信度差距 < 0.2。

执行逻辑：主索引主动向用户发起澄清询问，列出置信度最高的2至3个候选领域，并简要说明每个领域的处理范围，供用户选择。例如："您的问题涉及【理赔处理】和【合规申诉】两个领域，请问您更关注哪个方面？"用户选择后，主索引记录确认意图（该意图在后续轮次中获得+0.3上下文加分），并执行相应路由。若用户在规定轮次内未做选择，则自动降级为兜底路由。

**3. 兜底知识（三级）**

触发条件：最高意图置信度 < 0.4。

执行逻辑：将请求路由至ins-knowledge子Skill，由知识库提供通用性保险知识回答。同时，主索引在输出中附带友好提示，引导用户提供更精确的描述，例如："我理解了您关于保险的问题，以下是一些通用信息。如果您能告诉我更具体的方向（如投保、理赔、保单等），我可以为您提供更精准的帮助。"兜底策略确保即使面对完全模糊的输入，系统也不会返回错误或空白响应，而是提供有价值的基础信息并引导用户细化需求。

## 工作流程

1. **接收输入**: 接收用户的自然语言请求，初始化或恢复当前会话状态。若为新会话，创建全新的会话上下文、PII映射表和对话历史记录；若为延续会话，加载已有会话状态并准备进行上下文感知的意图识别。

2. **安全脱敏**: 调用security-guardian对输入进行PII脱敏扫描。识别并替换姓名、身份证号、手机号、银行卡号、保单号、地址、邮箱等敏感信息为标准化占位符（如`<PII_NAME_1>`、`<PII_ID_1>`）。生成PII映射表并存储于会话状态中，供后续还原阶段使用。若输入中包含高风险敏感信息（如完整身份证号+姓名组合），额外记录安全审计日志。

3. **意图识别**: 主索引内部的意图识别引擎加载 `router.yaml` 路由表配置，对脱敏后的用户输入执行三重信号分析。首先进行关键词匹配，计算各子Skill的关键词命中得分；其次通过预训练语言模型编码用户输入和Skill描述，计算语义相似度；最后结合会话上下文（对话历史一致性、跨Skill场景命中、用户确认意图）计算上下文加分。将三项信号按权重融合后通过softmax归一化，得到各子Skill的意图置信度分布。

4. **路由决策**: 根据意图置信度分布和降级策略进行路由决策。若最高置信度超过0.7且Top2差距足够大，执行直接路由；若置信度处于中间区间或Top2接近，执行澄清询问流程；若置信度低于0.4，执行兜底路由至ins-knowledge。若用户输入同时命中跨Skill协同场景的关键词组合，则优先触发协同链调度，覆盖单一路由决策。

5. **子Skill调度**: 将脱敏后的输入（以及必要的会话上下文和协同链配置）发送给目标子Skill。单Skill场景直接发起单次调用；协同链场景按序或并行发起多次调用，主索引监控各调用状态，处理超时、异常和失败情况。对于串行协同链，将前一Skill的结构化输出作为后一Skill的输入参数传递。

6. **结果聚合**: 接收各子Skill的返回结果。单Skill场景直接保留原始输出；多Skill协同场景执行智能聚合，包括信息去重（消除各Skill输出中的重复内容）、优先级排序（按领域相关性和置信度排列）、冲突检测（标识不同Skill结论不一致之处并标注供用户参考）和统一格式化（确保输出风格、术语和结构的一致性）。

7. **安全还原**: 调用security-guardian，使用会话状态中存储的PII映射表，将输出中的占位符还原为原始敏感信息。还原过程遵循最小必要原则，仅还原用户明确需要知晓的PII（如用户询问自己的保单信息时还原保单号），对于无需展示的高风险信息保持脱敏状态。

8. **输出过滤**: 对还原后的输出进行二次安全扫描，确保无PII泄露、无敏感信息意外暴露、无不符合合规标准的内容。扫描规则包括：正则表达式匹配常见PII格式、关键词黑名单过滤、输出长度合理性检查。若发现异常，触发安全告警并将输出降级为安全提示信息。

9. **本地评价**: 调用local-evaluator组件，由大模型对最终输出进行8维度语义质量评价。评价维度涵盖准确性（内容是否正确）、完整性（是否覆盖用户全部需求）、相关性（是否与用户问题高度相关）、安全性（是否符合安全与合规要求）、可读性（表达是否清晰易懂）、时效性（信息是否及时有效）、一致性（内部逻辑是否自洽）和实用性（是否对用户有实际帮助）。评价结果存储于会话日志中，用于平台服务质量监控。

10. **返回结果**: 将经过安全还原、输出过滤和质量评价的最终结果返回给用户。根据路由类型附加不同的元信息：单Skill路由标注来源子Skill；协同路由按执行顺序分段展示并标注各段来源；降级场景附带友好提示和建议方向。更新会话状态，记录本轮对话的意图、路由路径和输出摘要，为下一轮对话提供上下文支撑。

## 输出规范

主索引本身的输出格式：
- 单Skill路由：直接透传子Skill输出，并在输出头部标注来源子Skill名称和路由置信度
- 多Skill协同：按执行顺序分段展示，每段标注来源子Skill名称和该段内容的领域归属
- 降级场景：友好提示 + 建议方向 + 可选的兜底知识内容
- 安全处理：所有涉及PII的输出均经过脱敏-还原闭环处理，确保敏感信息安全
