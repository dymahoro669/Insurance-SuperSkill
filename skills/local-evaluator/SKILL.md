## 能力描述

本地评价器是 Insurance-SuperSkill 平台的智能质量评价组件，采用 **LLM-as-Judge** 架构，充分利用大语言模型强大的语义理解、逻辑推理和领域知识能力，对 Skill 输出进行深度质量评估。每次 Skill 调用完成后，评价器将 Skill 的输出内容、原始用户输入、以及结构化评价 Prompt 一起提交给大模型，由大模型从八个维度进行语义级质量判断。相比传统规则引擎，LLM 评价器能够识别深层逻辑问题、语义不一致、专业深度不足、隐含合规风险等规则难以捕捉的质量缺陷，实现真正意义上的智能质量管控。

### 八维度评价体系

评价器构建了覆盖结构、内容、合规、语义、逻辑的全方位评价矩阵，八个维度及其权重分配如下：

- **D1 输出结构完整性（weight: 20%）**：检查输出是否包含该 Skill 定义的必要字段和结构。不同 Skill 有各自的必要字段清单（如理赔 Skill 需包含材料清单、结论、时间预估），字段缺失将直接影响得分。该维度权重最高，确保输出在骨架层面满足业务要求。

- **D2 术语规范性（weight: 15%）**：评价保险专业术语使用是否准确、标准。大模型会识别术语误用（如将"免赔额"与"起付线"混淆）、非标准表述、过度口语化导致专业度下降等问题，保障输出的行业专业性。

- **D3 长度合理性（weight: 10%）**：评价内容详略是否得当。理想长度区间为 200-3000 字，过短可能导致关键信息遗漏，过长则可能包含冗余内容影响阅读效率。

- **D4 合规红线（weight: 20%）**：严格检查输出是否存在误导性承诺、违规表述、歧视性语言或虚假权威背书。这是保险行业最关键的质量维度，涵盖绝对性承诺（如"保证理赔"）、虚假权威（如"监管推荐"）、误导性比较（如"最便宜"）、歧视性表述、未经授权的专业建议等五大类风险。

- **D5 格式规范（weight: 10%）**：检查输出格式是否符合要求，包括 Markdown 标题层级、表格结构、列表格式、JSON 合法性等。

- **D6 数值合理性（weight: 10%）**：检查输出中的保费、赔付金额、费率等数值是否在合理范围内。核心规则包括：年保费通常不超过保额的 30%；赔付金额不应超过保单限额；比例类数值应在合理区间；数值之间需逻辑自洽。

- **D7 语义一致性（weight: 10%）**：评价输出是否真正回答了用户提出的问题，是否存在答非所问或偏离主题的情况。大模型会将 Skill 输出与用户原始问题进行深度语义比对，识别表面相关但实际未回应核心诉求的情况。

- **D8 逻辑自洽性（weight: 5%）**：检查输出内部是否存在自相矛盾或不一致的表述，如前后结论冲突、数值矛盾、推荐方案与结论不一致等。

### 硬规则与分级机制

评价器在 LLM 评分基础上，执行三层硬规则确保底线质量：

1. **D4（合规红线）< 60 → 整体降为 fail**：合规是保险行业的生命线，任何触及合规红线的输出无论其他维度表现如何，整体评价直接判定为失败，必须拦截并返工。

2. **D7（语义一致性）< 40 → 整体降为 fail**：如果输出完全答非所问或未能回应用户核心诉求，即使结构完整、术语规范，对用户而言也是无效输出，整体判定为失败。

3. **D1（结构完整性）< 40 → 整体最高 warn**：结构严重缺失的输出无法通过，但允许在 warn 级别进行提示性改进，给 Skill 一定的容错空间。

评价结果分为三级：
- **pass（通过）**：综合分 ≥ 80，所有维度无 fail，输出质量达标可直接交付。
- **warn（警告）**：综合分 60-79，或某一维度得分 < 60（但非硬规则维度），输出存在明显问题需要改进建议。
- **fail（失败）**：综合分 < 60，或触发硬规则（D4 < 60 或 D7 < 40），输出质量不达标必须拦截。

### 评价 Prompt 模板设计

评价器采用精心设计的结构化 Prompt 模板，包含角色定义、评价维度、评分标准、输出格式四个核心部分。角色定位为"专业的保险行业 AI 输出质量评价专家"，确保评价视角的专业性和客观性。每个维度配备独立的 prompt_template，支持动态注入 Skill 特定的必要字段清单（required_fields_by_skill）和用户原始问题（user_input），实现评价模板的灵活复用与精准适配。

### 与 L2/L3 评价服务的联动机制

本地评价器作为 L1 层实时评价节点，与上层评价服务形成三级联动体系：

- **L1（本地评价器）**：每次 Skill 调用后立即执行，耗时 < 2s，实现毫秒级质量拦截。fail 级输出直接阻断返回，warn 级输出附带改进建议仍允许通过，pass 级输出正常放行。

- **L2（批量质量监控）**：定时汇总 L1 评价数据，进行趋势分析和异常检测。当某 Skill 的 warn/fail 率超过阈值时，触发 Skill 进化流程，自动通知对应 Skill 的维护者进行优化。

- **L3（人工审核闭环）**：对 L1 判定为 fail 的高风险输出进行人工抽样复核，校准 LLM 评价器的评分偏差，持续优化评价 Prompt 和阈值设定，形成"评价-反馈-进化"的闭环质量生态。

### 改进建议生成

评价器不仅输出评分，还会基于低分维度的具体理由，自动生成可操作的改进建议。建议生成逻辑内嵌于评价 Prompt 中，由 LLM 根据评分理由提炼出 1-3 条针对性优化方向，帮助 Skill 开发者快速定位问题并迭代改进。

## 工作流程

1. **接收评价请求**：接收主索引发送的评价请求（包含用户原始输入、Skill ID、Skill 输出内容、期望格式等元信息）。请求经过基本的参数校验后进入评价队列。

2. **加载评价模板**：从 `evaluator/rules.json` 加载该 Skill 对应的评价维度模板和配置参数，包括 LLM 模型配置（默认 claude-sonnet-4-6，temperature=0.1 确保评分稳定性）、各维度权重、必要字段清单等。

3. **构建评价 Prompt**：组装结构化评价 Prompt。首先注入系统角色定义，然后按 Skill 类型动态替换必要字段占位符（如理赔 Skill 替换为"材料清单、结论、时间预估"），注入用户原始问题用于语义一致性评价，最后拼接八个维度的评价指令和输出格式要求。

4. **调用 LLM 评价**：将构建好的 Prompt 提交给大模型 API，获取语义级质量判断。LLM 基于其保险领域知识和推理能力，对每个维度给出 0-100 的整数评分和简要理由。

5. **解析评分结果**：解析 LLM 返回的结构化评分 JSON，提取各维度得分、综合得分、评级和改进建议。对解析异常的情况进行容错处理，记录错误日志并触发降级策略。

6. **规则预检辅助**（可选）：对明显问题（如输出为空、格式完全错误、包含已知违禁词）进行快速规则预检，作为 LLM 评价的补充。规则预检发现的问题会与 LLM 评分进行交叉验证，提升评价可靠性。

7. **硬规则判定**：依次执行三条硬规则：检查 D4 是否 < 60（合规红线）、D7 是否 < 40（语义一致性）、D1 是否 < 40（结构完整性）。任一硬规则触发即按规则调整最终评级。

8. **综合判定与输出**：根据加权综合得分和硬规则调整后的评级，输出 pass / warn / fail 最终判定。同时附带八个维度的详细评分、理由说明和 1-3 条改进建议，形成完整的评价报告返回给调用方。

## 评价维度（8维）

| 维度ID | 维度名称 | 评价内容 | 权重 |
|--------|---------|---------|------|

| D2 | 术语规范性 | 保险专业术语使用是否准确、标准 | 15% |
| D3 | 长度合理性 | 内容详略是否得当，无冗余或遗漏 | 10% |
| D4 | 合规红线 | 是否存在误导性、违规或违禁表述 | 20% |

## 评分标准

- **pass（通过）**：综合分 ≥ 80，所有维度无 fail
- **warn（警告）**：综合分 60-79，或某一维度得分 < 60
- **fail（失败）**：综合分 < 60，或 D4（合规红线）得分 < 60，或 D7（语义一致性）得分 < 40

## 硬规则说明

| 规则编号 | 触发条件 | 影响 |
|---------|---------|------|
| H1 | D4（合规红线）< 60 | 整体评级强制降为 fail，无论综合得分高低 |
| H2 | D7（语义一致性）< 40 | 整体评级强制降为 fail，输出未回应用户核心诉求 |
| H3 | D1（结构完整性）< 40 | 整体评级最高为 warn，结构严重缺失不可直接通过 |

硬规则的设计哲学是：合规和语义是保险 AI 输出的底线要求，结构完整性是基本门槛。任何触及底线的输出都不应以高综合分蒙混过关，确保评价体系的公正性和业务安全性。
